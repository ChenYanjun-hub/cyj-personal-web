## A. 完整版（框架模板：背景 → 工作内容 → 成果）

```
同舟建景规划规范问答助手｜内部 AI 应用项目牵头人          2025.12—2026.02

【项目背景】
现行设计规范体系庞大（2000+ 部），规划师日均需 1–2 小时翻阅 PDF 查条文；而通用大模型
查规范会编造规范号、条文号与数值，在"像查法条"这类低容错场景等同不可用。项目目标是做
一款可溯源、不编造的专业规范 RAG 问答产品。

【工作内容】：负责产品 0→1 全流程，包括需求定义与 PRD、知识库建设、RAG 链路设计、
评测体系构建与 Agent 架构设计。

● 产品与规则定义：输出完整 PRD，定义 4 条不可妥协红线（不编造 / 引用精确 / 强制性用语
  "应-宜-可"不可错 / 不给规范外建议），并将红线转化为可自动检测的后处理规则与评测一票否决项。

● 知识库构建：清洗并结构化 6 个领域、89 部规范、10,785 条条文；以"条"为分块单元、表格与
  公式独立成块并保留规范号/条文号/页码元数据，支撑条文级精确引用与原文跳转。
  （来源：backend/data/chunks 索引统计）

● 评测体系构建：建立 171 题、7 维度离线评测 + 3 项一票否决；针对单次 LLM Judge 约半数为
  噪声的问题，采用三次交集 + 方差分析剥离判官噪声后再认定真实缺陷。
  （来源：docs/eval/W7_D5_variance_report.md）

● 评测保真与 Badcase 归因：逐条审计 29 例检索失败的「期望条原文 vs 实际召回原文」，发现
  约三分之一为评测集自身标注错误；校准 ground-truth 并引入多值 GT（一题可接受多个合法出处）
  后，条文级 Hit@5 由 78.8% 提升至 89.8%，且未改动任何检索代码。
  （来源：docs/eval/2026-W7_baseline_v5_171_miss_audit.md；口径：strict Hit@5，137 题可答样本）

● Agent 架构设计：设计并落地查询分解（发散/复合问题拆解为子问题分别检索再合并）、引用核验
  （LLM 逐项核对答案中规范号/条文号/数值是否有据）、工具调用（ReAct + Function Calling 精确
  查表）三个 Agent，并增加规则调度层，使简单查询不触发任何额外模型调用、TTFT P95 约 1.2 秒。
  （来源：backend/scripts/perf_probe.py 22 条实测）

● Agent 评测体系：建立 48 题路由评测集（含 10 题"措辞像发散、实为单点"的对抗样本），定义
  误触发率 / 漏触发率作为 Agent 决策指标；路由准确率 93.8%、清晰样本 100%、漏触发率 0%。
  （来源：backend/scripts/run_agent_eval.py）

【项目成果】
综合质量分 86.6→90.3，一票否决项 38→13，原文用词准确率 86.2%→94.0%；条文级检索
Hit@5 78.8%→89.8%；覆盖 6 领域 89 部规范 / 10,785 条条文；评测集自 50 题扩至 171 题并新增
48 题 Agent 路由评测集；沉淀 87 条可迁移 AI 产品方法论与 109 项自动化测试。
```

## C. ⚠️ 差异化提示（与队友「设计规范智能问答 ganet」高度同类，务必执行）

| 维度 | 我的独有资产（队友大概率没有） |
|---|---|
| **评测保真** | 审计出评测集自身标注错误、并用"零代码改动提升 11pp"证明——**这是极少有人做的反向操作** |
| **Agent 评测** | 误触发率/漏触发率、路由评测集、对抗样本——**给 Agent 建评测，而非只给模型建评测** |
| **克制的判断** | 有 Agent 方向诊断后**主动不做**（国标优先重排：诊断发现目标根本未被召回，boost 无效）|
| **完整 PRD + 领域理解** | 规划专业背景 → 真懂"应/宜/可"的法律效力差异，红线不是抄来的 |

**表述避雷**：不要用"召回率 100%""准确率 95%"这类无口径大数；我的数字全部带口径与样本量，被追问只会更稳。
